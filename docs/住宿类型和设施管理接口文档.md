# 住宿类型和设施管理接口文档

## 1. 概述

本文档详细说明了住宿类型和设施管理的相关接口。为了更好地管理住宿信息，我们将住宿类型和设施信息独立出来，形成单独的管理接口，便于维护和扩展。

## 2. 数据库表结构

### 2.1 住宿类型表 (accommodation_types)

| 字段名 | 类型 | 描述 |
|--------|------|------|
| id | int | 住宿类型ID |
| name | varchar(50) | 类型名称 |
| description | text | 类型描述 |
| create_time | datetime | 创建时间 |
| update_time | datetime | 更新时间 |

### 2.2 住宿设施表 (accommodation_facilities)

| 字段名 | 类型 | 描述 |
|--------|------|------|
| id | int | 设施ID |
| name | varchar(50) | 设施名称 |
| description | text | 设施描述 |
| icon | varchar(255) | 设施图标 |
| create_time | datetime | 创建时间 |
| update_time | datetime | 更新时间 |

### 2.3 住宿设施关联表 (accommodation_facility_relations)

| 字段名 | 类型 | 描述 |
|--------|------|------|
| id | int | 关联ID |
| accommodation_id | int | 住宿ID |
| facility_id | int | 设施ID |
| create_time | datetime | 创建时间 |
| update_time | datetime | 更新时间 |

## 8. 注意事项

1. 所有时间字段格式为：`yyyy-MM-dd HH:mm:ss`
2. 新增和修改接口会对名称字段进行非空验证
3. 删除操作为逻辑删除，不会真正从数据库中移除数据
4. 分页查询页码从1开始计数
5. 管理员接口需要相应的管理员权限才能访问
6. 住宿设施关联通过中间表实现，查询时自动包含关联的设施信息

## 9. 旅游向导地图路线表设计

### 9.1 需求说明

为了在“旅游向导图”页面中保存每个打点地点的经纬度，并能够按照先后顺序组成一条完整的游览路线，需要设计一张专门的路线表（以及路线节点表）。

设计目标：
- 支持同一条路线包含多个打点地点；
- 每个地点保存名称、说明、经纬度信息；
- 按照先后顺序组成一条路线（使用顺序号字段）；
- 后续可以扩展多条不同主题路线（例如：一日游、夜景游、美食路线等）。

### 9.2 路线表 (guide_routes)

| 字段名 | 类型 | 描述 |
|--------|------|------|
| id | int | 路线ID（主键，自增） |
| name | varchar(100) | 路线名称，例如“江北嘴一日游” |
| description | text | 路线描述、游玩说明 |
| total_distance | decimal(10,2) | 预估总距离，单位：公里，可选 |
| total_duration | int | 预估总时长，单位：分钟，可选 |
| create_time | datetime | 创建时间 |
| update_time | datetime | 更新时间 |
| status | tinyint | 状态：0-禁用，1-启用 |

### 9.3 路线节点表 (guide_route_points)

| 字段名 | 类型 | 描述 |
|--------|------|------|
| id | int | 节点ID（主键，自增） |
| route_id | int | 所属路线ID，对应 guide_routes.id |
| step_order | int | 在路线中的顺序（从1开始递增） |
| name | varchar(100) | 地点名称，例如“江北嘴大剧院” |
| address | varchar(255) | 地点地址，可选 |
| latitude | decimal(10,6) | 纬度 |
| longitude | decimal(10,6) | 经度 |
| stay_minutes | int | 建议停留时长（分钟），可选 |
| remark | text | 备注说明，例如“拍照点”、“适合傍晚到达”等 |
| create_time | datetime | 创建时间 |
| update_time | datetime | 更新时间 |

经纬度字段说明：
- latitude、longitude 使用 decimal(10,6)，可以精确到约 0.11 米，足够满足地图打点需求；
- 在前端可以直接将这两个字段传给地图组件（如高德/百度/腾讯地图）进行标注。

### 9.4 建表 SQL 示例

```sql
CREATE TABLE guide_routes (
  id INT AUTO_INCREMENT PRIMARY KEY COMMENT '路线ID',
  name VARCHAR(100) NOT NULL COMMENT '路线名称',
  description TEXT NULL COMMENT '路线描述',
  total_distance DECIMAL(10,2) NULL COMMENT '预估总距离(公里)',
  total_duration INT NULL COMMENT '预估总时长(分钟)',
  status TINYINT NOT NULL DEFAULT 1 COMMENT '状态：0-禁用，1-启用',
  create_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  update_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间'
) COMMENT='旅游向导地图路线表';

CREATE TABLE guide_route_points (
  id INT AUTO_INCREMENT PRIMARY KEY COMMENT '节点ID',
  route_id INT NOT NULL COMMENT '所属路线ID',
  step_order INT NOT NULL COMMENT '在路线中的顺序',
  name VARCHAR(100) NOT NULL COMMENT '地点名称',
  address VARCHAR(255) NULL COMMENT '地点地址',
  latitude DECIMAL(10,6) NOT NULL COMMENT '纬度',
  longitude DECIMAL(10,6) NOT NULL COMMENT '经度',
  stay_minutes INT NULL COMMENT '建议停留时长(分钟)',
  remark TEXT NULL COMMENT '备注说明',
  create_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  update_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  CONSTRAINT fk_guide_route_points_route
    FOREIGN KEY (route_id) REFERENCES guide_routes(id)
) COMMENT='旅游向导地图路线节点表';
```

### 9.5 前端使用建议

- 创建路线时：
  - 先保存一条 guide_routes 记录，拿到 route_id；
  - 在地图上按顺序选点，每个点保存为一条 guide_route_points 记录，step_order 从 1 开始递增；
- 回显路线时：
  - 按 route_id 查询所有节点，并按 step_order 升序排序；
  - 将点位依次连线，形成完整的地图路线；
- 如果只需要一条固定路线，也可以先约定 route_id = 1，直接针对这一条路线维护节点即可。
